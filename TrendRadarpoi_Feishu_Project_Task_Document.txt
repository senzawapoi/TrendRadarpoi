TrendRadarpoi Feishu 项目任务文档 版本：v1.0 目标：将 TrendRadarpoi
升级为个人 AI 情报助手，并以飞书作为主要交互入口。

一、项目定位

项目不再定位为单纯新闻热点推送工具，而升级为：

“个人信息采集、分析、研究与对话助手”。

核心能力：

1.  每日自动采集：

-   科技新闻
-   AI 动态
-   GitHub 趋势
-   安全情报
-   RSS 信息

2.  AI 分析：

-   Gemini 负责摘要、翻译、分析
-   判断信息价值
-   生成个人日报

3.  对话能力：

-   通过飞书 Bot 与助手聊天
-   查询历史情报
-   追问新闻背景
-   触发互联网研究

4.  外部研究能力：

-   Agent-Reach 作为互联网信息能力层
-   按需搜索 Web、GitHub、Reddit、YouTube 等资源

二、整体架构目标

最终架构：

用户 | 飞书 Bot | Assistant Layer | Gemini | +—————-+ | | 本地情报库
Agent-Reach | | TrendRadar 外部搜索 | SQLite

三、部署规划

当前 VPS：

CPU: Intel Xeon E5-2698 v4 1 Core

Memory: 1.87GB RAM

建议：

短期： GitHub Actions + VPS 混合

GitHub Actions： - CI - 测试 - 定时任务迁移准备 - 备份

VPS： - 飞书 Bot - Gemini Assistant - SQLite - Agent-Reach - 长连接服务

长期：

VPS 作为主要 Runtime。

GitHub Actions 作为： - CI/CD - 备份 - 手动恢复

四、飞书接入任务

目标：

实现：

用户 -> 飞书 -> TrendRadar Assistant -> Gemini -> 回复

任务：

1.  创建飞书机器人应用

2.  实现消息接收

功能：

-   接收用户问题
-   判断意图
-   查询本地数据库
-   调用 Gemini
-   返回结果

3.  权限控制

必须加入：

allowed_users

只允许个人账号使用。

五、Gemini Assistant 重构任务

当前：

Gemini 主要用于翻译。

升级：

抽象：

GeminiClient

能力：

1.  TranslationService

2.  DailyDigestAnalyzer

3.  SecurityAnalyzer

4.  ChatAssistant

5.  ResearchOrchestrator

原则：

MCP 不作为核心服务依赖。

核心服务调用 Gemini。

MCP 作为外部访问接口。

六、Agent-Reach 集成任务

定位：

不是 crawler。

不是数据采集 pipeline。

定位：

互联网研究能力层。

设计：

Gemini | ResearchGateway | Agent-Reach

提供接口：

search_web()

search_github()

search_reddit()

read_webpage()

get_video_transcript()

禁止：

直接开放 shell 执行。

七、cybersecurity-daily 融合计划

不直接合并代码。

吸收：

1.  安全日报生成逻辑

2.  CVE 信息筛选

3.  威胁情报总结

新增：

security domain

包含：

security collector

security analyzer

security report

数据来源：

-   CISA KEV
-   NVD
-   安全 RSS
-   安全新闻

title

url

content

十、数据库规划

十三、最终目标

TrendRadarpoi 最终形态：

每天：

自动收集信息

↓

AI 判断重要性

↓

发送个人日报

需要时：

用户通过飞书询问：

“最近 AI 有什么重要变化？”

系统：

查询历史数据

不足时调用 Agent-Reach

Gemini 综合分析

返回答案。

项目目标：

成为个人长期使用的 AI 情报助手。
