# Plan 04: Deduplicate, Rollback, and Backfill

## Objective

Complete conservative deduplication, canonical-first translation, runtime rollback, failure
degradation, and explicit historical backfill.

## Tasks

1. Apply observation identity, canonical URL, same-source exact title, then same-source fuzzy title
   rules with a 24-hour window, minimum title length 12, and ratio 0.92.
2. Preserve every duplicate as an observation and keep stored canonical IDs stable. Translate one
   representative per canonical ID and propagate translations to legacy records.
3. Add YAML/environment settings for unified enablement and database path. Continue the legacy
   delivery path if unified storage cannot open or write, without refetching upstream.
4. Add the idempotent `trendradar.intelligence.backfill` command with date range, source filters,
   dry-run, chronological processing, and corrupt/missing database handling.
