<objective>
Define serializable Cluster and Story domain models and a deterministic, offline clustering
engine for canonical ContentItem batches. The output must be stable regardless of input order,
must preserve singleton items, and must not touch legacy models or databases.
</objective>

<tasks>

<task type="implementation">
  <name>Model Cluster, Story, and importance value objects</name>
  <files>trendradar/core/models/story.py, trendradar/core/models/__init__.py</files>
  <action>
    Add UTC-validated dataclasses for Cluster and Story plus an ImportanceBreakdown value object.
    Give every object deterministic serialization/deserialization, stable IDs, member IDs,
    event time, domain, tags, title, summary, and component/reason fields. Use UUIDv5 over a
    documented signature for identities; never derive identity from list order. Export the public
    types from core.models without importing network clients. Preserve empty optional timestamps
    and JSON-safe metadata.
  </action>
  <done>Cluster, Story, and ImportanceBreakdown are exported, UTC-validated, JSON-round-trippable, and use order-independent UUIDv5 identities.</done>
  <verify>python -m pytest tests/intelligence/test_story.py -q</verify>
  <acceptance_criteria>Models reject naive timestamps/empty required fields, round-trip JSON, and
  produce the same IDs from the same logical signature in reversed member order.</acceptance_criteria>
</task>

<task type="implementation">
  <name>Implement deterministic clustering</name>
  <files>trendradar/intelligence/clustering.py</files>
  <action>
    Implement pure cluster_items(items, config=None) using stable sorting by event time and ID,
    24-hour buckets, normalized title tokens, tags, and configured entity keywords. Use
    conservative shared-entity/tag plus token similarity rules, reject conflicting non-empty
    entities, and create a singleton Cluster when no candidate matches. Use a deterministic
    union-find/component pass and stable cluster signatures. Do not perform I/O or call Gemini.
    Expose small helpers for event time, token/entity extraction, and similarity so thresholds
    can be tested and versioned.
  </action>
  <done>cluster_items performs stable, offline connected-component clustering with conflict guards, bounded time windows, and singleton output.</done>
  <verify>python -m pytest tests/intelligence/test_clustering.py -q</verify>
  <acceptance_criteria>Same events from different sources merge; unrelated entities remain
  separate; tags/title/time affect matching; singleton and reversed-input cases are stable.</acceptance_criteria>
</task>

<task type="test">
  <name>Lock model and clustering contracts</name>
  <files>tests/intelligence/test_story.py, tests/intelligence/test_clustering.py</files>
  <action>
    Add focused fixtures for UTC timestamps, cross-source same-event titles, conflicting entity
    names, tags, outside-window items, empty content, singleton clusters, deterministic IDs,
    serialization, and input-order permutations. Assert no network or database dependency.
  </action>
  <done>Focused model and clustering tests cover all declared signals, failure boundaries, and reversed-input determinism.</done>
  <verify>python -m pytest tests/intelligence/test_story.py tests/intelligence/test_clustering.py -q</verify>
  <acceptance_criteria>Tests directly cover CLUS-01, CLUS-02, and the model portion of STOR-01.</acceptance_criteria>
</task>

</tasks>

<dependencies>
Phase 1 ContentItem and normalization APIs are the only upstream dependency. Storage integration
is intentionally deferred to 02-02; this plan's clustering function remains side-effect free.
</dependencies>

<risks>
Conservative thresholds may split ambiguous events, while broad title matching may merge unrelated
events. Entity conflict guards, fixed time windows, and explicit tests are the mitigation; threshold
values must be recorded in the model/generator version.
</risks>
