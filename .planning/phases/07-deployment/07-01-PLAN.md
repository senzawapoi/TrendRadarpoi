# 07-01 Plan: Runtime Roles and Scheduling

## Goal

Split the Lark runtime into independently runnable Bot, Worker, and one-shot
Scheduler roles while keeping the combined entry point compatible.

## Tasks

1. Add `--role {combined,bot,worker,scheduler-once}` and role-specific offline
   validation to the public Lark entry point.
2. Make Bot use `EventLedger.record()` as the durable handoff and stop depending
   on an in-process queue for correctness.
3. Make Worker poll and claim durable events with bounded idle/error backoff;
   it must not create a WebSocket connection or run Scheduler ticks.
4. Make Scheduler run exactly one existing `DeliveryScheduler.tick()` and exit.
5. Add shared OS role locks and a separate collection lock helper.
6. Add Linux unit/timer templates with absolute paths and explicit config/data
   directories. Templates are not proof of installation.
7. Add focused tests for role isolation, duplicate suppression, polling, and
   `--check` no-I/O behavior.

## Acceptance

The four roles import offline, `--check` creates no database, Bot alone owns
transport, Worker alone consumes durable events, Scheduler does not consume
chat, and competing role instances are rejected. Existing runner tests and
legacy entrypoints remain green.
